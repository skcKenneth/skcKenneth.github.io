# 第二輪網站完善方案：有溫度的知識書刊

狀態：2026-10-11 已獲用戶批准並設為執行目標。先完成 `consolidation-audit.md` 所列功能入口統整、驗證及發布，再依次實行以下三批。各批完成情況以實際驗收及發布紀錄為準。

基準：已發布的 `6a54eda`。已直接查看正式網站首頁及主題頁，並閱讀目前首頁、卡片、文章、教學與作者流程的實作。網頁搜尋快取仍顯示較舊版本，因此現況判斷以正式瀏覽器與目前程式為準。

## 方向與現況判斷

沿用一般網誌讀者優先、米白 `#f5f3ed`、墨綠 `#1f6652`、交織 icon、四項主導覽、八個固定主題，以及 Astro／GitHub Pages。上一輪的搜尋、收藏、RSS、目錄與發布流程繼續作為基礎。

目前最有價值的下一步：

- 桌面介紹區佔大部分首屏；可以精簡版面，讓文章更早出現。
- 最新文章縮圖直接使用研究圖，細小圖中文字難以在卡片尺寸閱讀。需要較清楚的封面構圖及主次。
- 主題頁已能找到文章，但按日期排序未能告訴新讀者應從哪篇開始、之後讀甚麼。
- 最新三篇閱讀時間分別約 26、27、29 分鐘。長文可以提供更明確的問題、先備知識與閱讀預期。
- 個人介紹以專業與研究為主；可透過有來源的短札記、寫作緣起與教學觀察，增加作者的聲音。

上述是編輯與設計判斷；本輪沒有量度流量、轉換率或實際讀者滿意度。

## 第一批：先讓版面更精緻，文章更容易開始

### 1. 建立一致的編輯視覺

- 首頁介紹改為較緊湊的文字與小型主題插畫組合。頁首保留交織標誌；介紹區用曲線、節點與幾何形狀延伸品牌。
- 米白與墨綠維持主色；淡鼠尾草、沙紙色及少量暖銅只作插畫和區塊點綴。正文、按鈕、狀態的對比另行驗證。
- 最新文章仍自動展示三篇、各出現一次。桌面採一篇主卡加兩篇精簡卡；手機依清楚閱讀順序排列。
- 建立「重點圖文卡／精簡文字卡」兩款共用組件，處理長標題、無圖文章與中英文長度差異。
- 為八個主題建立同一線寬與構圖語言的簡潔 SVG 圖案。
- 先為六篇選讀製作可在小尺寸辨認的編輯封面。示意插畫清楚作為封面；正文科學圖件、比例與圖說維持原意。
- 延伸現有分享圖產物流程，為這六篇生成帶實際標題的個別分享 PNG，沿用輸入／輸出雜湊紀錄。

首頁保持五段：簡短介紹 → 最新三篇 → 入門選讀與一個專題捷徑 → 八個主題 → 精簡教學入口。

### 2. 六篇長文試行讀前指南

優先挑選內容完整、適合一般讀者進入的六篇。

首輪候選：〈兩個網絡，同一組特徵值，不同警報〉、〈優化器漏掉了多少個平衡態？〉、〈交通模型要記住甚麼？少看一些狀態，會否判錯穩定性？〉、〈當擬合不等於模型本身〉、〈隨機壓力測試不是最壞情況證書〉、〈當太陽能發電急升急跌：預測區間改善了，為甚麼仍不夠可靠？〉。它們涵蓋目前最新文章、一般模型判斷及已有教學研究案例。

每篇整合原有摘要及來源提示，提供：

- 一句核心問題。
- 兩至三點閱讀看點。
- 適合對象及必要先備知識。
- 研究文章的一句證據或限制提示。

指南內容只從正文已支持的資訊整理，中英文成對管理。手機常駐核心問題，其餘可展開，控制正文前的高度。資料尚未編輯完成的文章沿用現有摘要。

**交付：** 首頁、主題詳情、文章三類版面的桌面與手機預覽；兩款卡片；八款主題圖案；六份封面、分享圖與雙語讀前指南。

**驗收：** 長標題完整顯示；小圖主形清楚；首頁最新文章仍只有三篇且不重複；手機能迅速看到核心問題；指南與研究正文、限制一致。

## 第二批：把分類變成真正的閱讀路線

### 3. 兩條人工編排的專題導讀

先試兩個方向，名稱及文章次序在選稿時核對：

| 試點 | 讀者問題 | 可用內容方向 |
|---|---|---|
| 模型可信度 | 擬合得好，為何仍可能判錯？ | 由模型與資料的差別，走到可辨識性、驗證與證書界限 |
| 城市中的數學 | 模型如何影響交通與工程判斷？ | 交通記憶、通風與其他已有城市工程案例 |

每條三至五篇已發布內容，以「理解問題 → 看一個例子 → 深入判斷」排列。每一步附閱讀目的、先備要求及約略時間；已有教學活動可作選讀延伸。

專題由主題頁進入，文章可顯示所在路線及下一步。八個主題 ID 繼續作穩定分類；路線以共同文章 ID 指向雙語版本。首頁選讀區放一個專題捷徑。

### 4. 八個常用概念的雙語導讀

先整理基準、假設、敏感度、可辨識性、校準、驗證、穩健性與不確定性。每個概念包括簡釋、一個例子、一個常見誤解、參考來源，以及相關文章／教材。

正文選定位置可按鍵或觸控展開解釋，並可到獨立詞條頁。沒有 JavaScript 時仍有正常連結；解釋並非只在滑鼠停留時出現。

### 5. 長文接續與列印

- 以文章共同 ID 及章節記住閱讀位置，提供「由上次位置繼續」與清除紀錄，沿用瀏覽器本機保存方式。
- 標題或章節更新後，失效位置返回文章入口並說明狀態；中英文版本按可對應章節處理。
- 文章列印版保留標題、日期、正文、圖表、參考資料及文章網址，適合瀏覽器存 PDF。

**交付：** 兩條雙語專題導讀、八個概念、六篇試點文章的概念入口，以及閱讀位置／列印工具。

**驗收：** 主題頁一次點擊可進入路線第一篇；次序及雙語對應一致；概念可用鍵盤開關；閱讀位置可以清除；A4 抽查中英文公式、圖說、長表格與程式碼；既有收藏及學習紀錄格式通過回歸。

## 第三批：增加作者聲音與可直接使用的教學內容

### 6. 短札記與個人介紹

在現有文章系統試行三篇較短內容，例如一個教學觀察、值得追問的小問題、研究中改變想法的地方。由已有材料或作者提供的想法整理，列入正常文章清單與 RSS。

關於頁增加「為甚麼寫這個網誌／如何選問題」的短段落，銜接現有專業介紹與已核實經歷。個人近況集中於關於頁，附更新日期，控制首頁篇幅。

### 7. 兩個可直接上課的課堂包

從現成資源選一個初中探究、一個建模活動，把文章、互動工具及練習編成清楚的一節課：

- 課前準備與適用對象。
- 活動時間及教學次序。
- 學生任務頁、教師參考及離堂問題。
- 投影、分享、列印與返回原資源的操作。

分享連結只帶課堂設定；學生入口清楚區分教師參考。原有題目、工具與學習紀錄保留。

### 8. 作者用的覆核佇列

在既有發布檢查旁新增本機報告，列出原文更新後尚未覆核的另一語言、教材來源版本變動，以及可能需同步修訂的導讀與路線。記錄內容指紋、覆核版本及實際結論；候選項由 Codex 按來源處理，無法確認的事實保持待核對。

**交付：** 三篇短札記、關於頁補充、兩個課堂包，以及內容同步覆核報告。

**驗收：** 短札記能由既有文章及 RSS 找到；個人敘述有來源；教師由教學總覽兩次點擊可開課；學生分享入口不帶個人紀錄；覆核報告能追溯版本且不改動歷史發布日期。

## 共同工程及驗收範圍

- 仍以靜態產生頁面及按需載入互動完成；新內容資料集中管理並保留中英文共同 ID。
- 畫面抽查 360、390、768、1280 px、200% 文字放大，以及鍵盤／焦點／減少動態效果。長文公式與表格使用各自的捲動區。
- 以 [WCAG 2.2](https://www.w3.org/WAI/WCAG22/quickref/) 的相關條目驗收新增控制、插畫與列印入口，記錄測試範圍。
- 先記錄同一裝置與網絡條件下的效能基準，再比較新版載入、互動與版面穩定性；參照 [Web Vitals](https://web.dev/articles/vitals)。首頁的編輯版面以靜態 HTML／CSS 為主，圖片沿用適當尺寸及預留空間；可使用 [Astro 的圖片功能](https://docs.astro.build/en/guides/images/)。
- 每批檢查舊網址、雙語對應、Pagefind、收藏、學習紀錄、數學排版及內容發布條件，完整建置後再發布和核對正式頁面。
- 請三種任務驗收：新讀者找到一篇合適文章並說出它回答甚麼；回訪讀者接續專題或長文；教師找到並開啟一個課堂活動。結果用來調整下一批範圍。

## 後續選項

完成三批後，再按需要選擇深色閱讀模式、跨研習室「我的學習桌」或小型互動知識地圖。它們分別需要處理科學圖的夜間呈現、不同學習紀錄的整合及額外導覽成本。

**推薦最先落實第一批。** 工程及編輯範圍有限，可以先看到全站觀感及入文體驗的變化，再決定第二批專題如何編排。
